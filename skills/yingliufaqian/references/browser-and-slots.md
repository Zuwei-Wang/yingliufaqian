# 官网协助与预约

## 能力与授权

先检查当前环境是否有浏览器工具，读其使用规范后操作。用实际页面文字和状态定位，不硬编码坐标、接口或过去的页面结构。无能力或登录受阻时，给出当前准确链接及逐步操作说明，保留已完成工作。

| 操作 | 处理方式 |
| --- | --- |
| 查看官方要求、进入公开页面 | 正常推进，记录来源和核查时间 |
| 读取用户已授权的账户页面 | 限于当前申请，避免查看其他人的申请 |
| 填写/保存申请草稿 | 在用户代填授权内执行；保存草稿也会把个人信息传给网站，不能当成本地操作 |
| 上传材料 | 需要用户已授权向这个网站提交这些材料；先确认域名和申请人，不能上传整个目录或多余文件 |
| 正式提交申请或声明 | 先完成准确摘要；授权应覆盖本次正式提交及声明，需本人签署/确认的步骤交给用户 |
| 查询空位 | 用户请求后在可访问的官方页面查询；可用不等于已预订 |
| 确认预约、付费、取消、改期 | 核对具体中心、时间、人数、服务、总价和取消条款；已有明确且足够具体的授权可执行，否则只问一次缺失的决策 |
| 登录、验证码、CAPTCHA、支付验证 | 交给用户在网站完成；不要索取密码或验证码到聊天/文件，不绕过反自动化机制 |

开发者让你“开发预约功能”不等于授权为开发者本人预约；测试只用合成信息及离线场景，不向真实申请表提交测试数据。

## 操作顺序

1. 从 `official-sources.md` 的 France-Visas 英国页面进入当前授权服务商，确认网址、英国及正确法国签证业务。不要使用广告中介链接；政府页面上的认证跳转可按实际证据核实。
2. 识别页面现在在哪一步，核对用户是否已有申请或预约，避免重复创建。未知字段停留在草稿。
3. 填表后逐字段复核，尤其姓名拼写、国籍、护照、目的、日期、住宿、资助和既往签证信息。不能为了省时接受预选的付费服务。
4. 正式操作前形成摘要供核对。缺少具体授权时，明确说明是哪项尚未授权的提交、预约或费用需要决定，不重复询问已获授权的操作。
5. 操作后读取成功页面或账户列表并保存正式回执。网络超时、支付结果不明时，先查询现有状态，不能盲目重试付款/预约。仍不明则标记“结果未知”，停止该提交步骤。

## Slot 查询与可选自动预约

第一版支持引导查询和经授权的页面操作；不内置后台监控器、私有 API 或自动抢号脚本。

查询前确认：可接受中心、日期区间、时段、申请人数、是否已有预约、费用上限、是否允许收费时段/附加服务。用户只问“有没有号”时可以先查，不应先索取一整套支付偏好。

默认在当前会话查询一次并报告“某时刻、某中心、某范围”的实际结果。没有空位只是这一范围和时刻的观察，页面错误或未登录不能解释为无号。

用户明确要求持续监控时，先核实网站条款和允许的访问方式，以及运行环境是否有可用调度器。未核实不得直接启动自动轮询。明确截止时间、检查频率、通知渠道和通知条件；遵循站点限速，出现 CAPTCHA、封禁提示、限流或登录过期时停止并提示用户。纯 skill 文件不能保证关机后或聊天结束后运行。

若要自动确认预约，授权必须覆盖候选中心、日期/时段、人数、总费用上限和可选服务；在提交时核对候选仍匹配。仅“帮我看号”或“有号告诉我”不包含预约/付款授权。禁止囤号、多账户规避、验证码代解和绕过队列。未获改期/取消授权不得动已有预约；不可在新预约未确认时先取消旧预约。

后台运行若获支持：状态不变时保持安静；只在匹配空位、执行结果、失败或需要用户动作时通知。预约成功、有明确停止请求、达到截止时间或访问异常即停止。记录实际结果，不承诺抢到号。
