# 材料工作规范

## 分类起点，不是统一必交清单

以下分类来自英国申请场景及历史案例，用于查漏。是否需要、时效、份数和格式由本次官方清单决定。

| 类别 | 可指导用户取得 | 核对重点 |
| --- | --- | --- |
| 申请表、回执、个人材料清单 | France-Visas 最终下载文件 | 正确申请人、正式版本、签名与日期；不把草稿当最终表 |
| 预约确认 | 当前授权服务商账户 | 申请人、中心、当地日期时间、确认状态 |
| 护照和照片 | 用户的原件、扫描件和合规格照片 | 签发/失效日期、空白页、需复制的签证和印章页、照片要求 |
| 英国居留证明 | GOV.UK eVisa 和所需 share code | 当前身份、有效期、正确用途；不要仅凭过期实体 BRP 判断现时居留 |
| 学生身份 | 按 [学校证明获取](university-documents.md) 查到的本校官方申请表或自助入口 | 优先核对适用于签证的证明类型；姓名、学校、在读状态、出具日期、所要求的签章或课程日期；不假设所有学校流程相同 |
| 财力证明 | 银行官方 statement 下载 | 本人姓名、所需地址、账户类型、连续期间、资金是否支持真实行程；截图不自动等同正式账单 |
| 资助材料 | 真实资助人证明及关系材料（若适用） | 不同资助关系按当前清单判断，不泛化配偶资助规则 |
| 交通 | 用户真实预订的确认文件 | 姓名、往返日期、跨境段及付款/预订状态；不能生成虚假出票凭证 |
| 住宿 | 酒店预订、租住或适用的接待证明 | 姓名、地址、每晚覆盖、真实预订状态；私人住宿不能冒充酒店订单 |
| 行程 | 用户确认的计划，可协助写成表格 | 每日城市、交通、住宿一致；“计划”不等于“已预订” |
| 保险 | 保险公司正式证明及必要条款 | 被保险人、覆盖地区、起止日期、保额、医疗/紧急治疗/遣返等适用要求 |
| 特殊情况说明 | 按真实事实起草解释信 | 只解释可支持的事实；解释信不能自动替代缺失的必需证明 |

历史样本包括按申请人分开的申请表、居留 status、share code、在读证明、银行材料、交通、酒店、行程、联名保险及预约确认。简历和中介信息采集表也可能出现，但不能据此认定是所有旅游申请人的必需材料。旧回执含实体 BRP 字样，不得作为当前要求直接照抄。

中介材料中的固定余额、开户天数、居留剩余天数、放号规律、迟到宽限等均未在此确认为通用官方规则。不要指导临时“做流水”，也不要建议用虚假行程或订单申请。

## 在私人目录整理

建议结构，用户已有结构可保留：

```text
申请目录/
  申请记录.md
  01_原始材料/       # 仅保存副本；用户原始文件保持原位置不变
  02_核对与草稿/
  03_官网回执/
  04_打印材料/
  文件索引.csv
```

不为所有用户扫描整个磁盘。只读用户选定范围；文件名只是线索，内容核对后再决定归属。无法读出的扫描件、密码 PDF 或不清楚的页面标为“待核对”，不绕过密码或猜测。

复制前检查目标同名文件，保留双方版本并用中性版本号区分。文件名使用材料类别和期间，不包含完整护照号、出生日期、账户号或 share code。已确认的每个文件记录相对路径、申请人代号、来源、页数、SHA-256（工具可用时）、检查状态和对应清单项。哈希只说明文件相同，不证明真实性。

多人共同文件可以作为引用或副本分别关联，但必须检查包含哪些申请人。没有某人的文件不意味着该人没有该项材料，未看见的信息写“未提供”。

## 补件、版本与状态同步

材料表是当前申请要求和缺项的统一记录；文件索引是文件证据与版本记录。给每条个性化要求一个稳定的清单项 ID，并保留官方原文位置。一个要求涉及多个文件时列出全部路径，必要时用子项（例如居留状态与 share code），不能只用“本轮更新”“打印项”代替映射。

用 [文件索引模板](../assets/file-index.csv) 建立新索引。现有索引可以保留格式，补齐同等信息即可。文件的版本角色区分 `当前采用`、`已替代`、`重复`、`待核对`；原始副本和打印副本用文件角色区分。历史观察单独记录发生日期和解决证据，不把已解决的“未提供 share code”等文字留在当前缺项/文件检查状态中。

每次补件、改行程或取得新清单时完成一次更新：

1. 核对新文件与适用的清单版本，确定对应清单项和当前采用的版本。若要求还不清楚，保留该具体问题，不能一律改成通过。
2. 更新材料表：关闭已有证据解决的缺口，记录解决日期和路径。只有一份文件的时效需要复核时，只更新相关项，不能让整表都显示未确认。
3. 更新索引：当前文件的状态与材料表一致；旧文件标明已替代及替代路径，历史缺口写清已解决。与该文件无关的全局待办（如另一张表待签）不能复制进它的状态。
4. 从当前材料表更新待办、打印清单和打印目录。保留历史副本在打印目录外；已打印用户需要一份“保留 / 重打 / 暂停用”的差异清单。新版完成前移出已失效的打印件，不靠文件名排序推测最新版本。
5. 重新读取落盘结果：每条当前要求能找到对应文件或明确缺口；每个打印文件都在索引中且路径、页数、哈希匹配；旧版和重复件没有混入；材料表、待办和索引没有互相矛盾的当前状态。签字、实物和备注列里的“待确认”也要核对，不能只看主状态列就宣布就绪。初步检查项若不属于当前要求，记录来源及不再适用的理由；若仍适用就保留缺口，不能把“已装包”推断成未确认的签字已完成。检查涉及的文件即可，不必重复渲染内容未变且已检查的 PDF。

继续上次申请时，先根据当前清单、有效文件和已记录的用户确认修复落后的派生记录。只有文件证据确实缺失、相互冲突或时效失效时才重新问用户；不要因为旧索引一句“待补充”而重问已提供的材料。

## 一致性与打印验收

1. 把用户本次官方清单逐条映射到文件，保留条件项和不适用理由，不凭类别数量宣布齐全。
2. 对照原件核对姓名及关键号码；摘要和通用日志尽量脱敏，完整值仅在必要的私人表格和正式文件里保留。
3. 核对日期链：离英、每个申根国家、每晚住宿、返英、保险，以及证件/证明有效性。计划变更后重新检查。
4. 银行材料核对官方所需期间和字段；资金不足或来源不明时描述实际缺口，不能自行得出必然拒签/必然通过结论。
5. 合并/旋转/转换只生成副本。完整保留必须提交的页、条码、签名和官方文字；不要编辑银行流水、学校证明、保险或预订的实质内容。
6. 检查所有最终页可读、无裁切、无重复或缺页；记录打印份数及单双面/彩色等要求的来源，未知时列为待核实，不冒充官方要求。
7. 可保留分类 PDF 并提供打印索引；是否合成单个 PDF 按用户需要和官方要求决定。选择合并包交付时，主打印目录默认只放当前完整包；分项文件或单页补打放入明确标注的备选子目录或核对目录，并注明与整包二选一，避免全选时重复打印。移动后同步索引和打印清单。未核对完的材料不能进入“已核对可打印”状态。

最终打印清单列：顺序、材料、文件/页数、原件、复印件份数、照片、签字、来源、完成状态。另列需随身携带且不能由文件包替代的实物。
