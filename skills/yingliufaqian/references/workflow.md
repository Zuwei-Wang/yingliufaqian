# 申请流程

## 1. 了解情况并确认路线

第一轮示例：“你在英国哪个城市？打算什么时候去法国、去做什么？已经填过表或约过号吗？”已提供的信息直接跳过；多国行程等影响类别的信息在相关判断前补问。

进度、偏好和下一步尽量让用户用字母选择，一轮围绕一个决策，通常2–3个实质选项加“其他”。保留“不确定”这个适用答案和自由输入，不为了选择题而强行限制事实。用户只回字母时按本轮选项解释并继续；字母有歧义才澄清，不能把选“帮我规划”当作购买或取消订单的授权。

根据回答继续收集，避免整张问卷一次发完：

| 当前决策 | 所需信息 | 判断与下一步 |
| --- | --- | --- |
| 能否使用主线 | 国籍、旅行证件类别、是否成年、英国居留类型及到期日 | 通过当次 Visa Assistant 核对；不把 UK Student/Graduate 身份当作法国签证类别 |
| 是否向法国申请 | 真实旅行目的、全部申根国家和各段日期、第一入境国 | 核对主要目的地规则；不能为了法签好约而虚构主要目的地 |
| 行程是否确定 | 日期/路线是确定还是暂定，交通和住宿是否已订 | 尚未确定或未订时按 [行程与可退款预订](travel-planning.md) 协助规划，比较具体机票、Eurostar等火车票及酒店的退款条件；已订则先核对现有订单 |
| 是否需要新签证 | 现有申根签证的有效期、入境次数、可停留天数、近期申根旅行 | 分清签证有效期和可停留天数；需要时使用官方短期停留计算器，不能只看签证到期日 |
| 时间是否可行 | 出发与返英时间、材料准备时间、护照其他用途 | 核对递交窗口、当前审理建议和预约；把预约等待、审理、护照返还分别考虑，不保证赶得上 |
| 中心怎么选 | 居住城市、可接受的中心及交通、可递交日期 | 先核对当前中心及限制，再按用户偏好推荐；不默认城市决定领区 |

未成年人、非普通护照、访友/探亲、欧盟家属、海外法国领地、长期学习/工作、英国居留待续、拒签或逾期等情况，应切换到相应官方类别核对。可以继续做文件整理和问题梳理，不能套用旅游默认清单或作出未经证实的资格结论。拒签申诉等专业事项先提供相应官方入口，不自动使用普通申请流程。

## 2. 建立个人准备计划

在申请记录中建立初步清单，标记“待 Visa Assistant / 当次申请回执确认”。每项记明取得方式和核对点；聊天先给最值得现在做的一项，用户需要总览时再展示完整清单。

按依赖安排：学校出具证明、银行历史账单等可以先准备；已确认的旅行安排可用于填写表格。不要强制等全部材料完成才开始预约，也不要在日期、申请类别和关键身份信息未确定时盲目提交。

未定行程时先提供“我帮你规划／自己安排／先准备其他材料／其他”的选择；愿意规划后按需补齐日期范围、城市和预算，再帮助选择可调整的安排，不强制先买不可退的交通住宿。可全额退款的真实预订是一种选择，是否预付仍由用户决定，具体凭证是否符合材料要求另按本次清单核对。

学校名称已知且证明缺失时，立即按 `university-documents.md` 找到具体办理入口；未知时只问学校名称，不把查路的工作交给用户。根据查到的办理时间安排先后，同时考虑证明在递交日的时效。等待学校出件期间推进其他材料，不反复催用户重申。

用户希望开始整理时，使用其选定的私人目录；若未指定则询问保存位置。用 `assets/case-template.md` 创建记录，保存当次官方来源和缺项，少记无关个人信息。多名申请人分别建档，共同行程和联名保险需逐人核对，不按“男/女”推断归属。

## 3. 协助申请表

进入正式申请、引导用户提交或支付签证费用前，先完成上表“是否需要新签证”的核对。首次办法签不等于没有其他申根签证；未知时用一轮简短选项确认，如“A 没有或已过期；B 有未过期或尚未生效的签证，请帮核对；C 不确定；D 其他”。有签证或不确定时先按本次旅行核对地域、类别、日期、次数和剩余停留额度，再结合当前官方规则判断新申请需求，不能直接让用户重复提交付费。已明确回答或已提供足够证据时不重问。

从官方入口进入 Visa Assistant，按真实国籍、居住地、目的和时长核查。页面动态内容无法读取时说明未验证，可交给用户完成并提供结果。

到具体字段时才收集需要的姓名拼写、护照信息、联系方式、学校信息、资金来源和行程。复用用户已确认的数据，标明来源与不确定项；OCR 或历史表格不能自动视为当前事实。没有资料的必填字段停下询问，不猜填。

官网表格草稿完成后，提供可核对摘要，重点突出身份、旅行日期、目的、住宿和资金承担。正式提交遵循浏览器操作授权范围。完成后下载最终申请表、回执及个人材料清单，核对申请人和版本，重新对齐材料表。

## 4. 预约与准备并行

根据当前官方链接进入授权服务商，将正确申请编号关联到正确申请人。日期、中心、人数、服务及费用偏好明确后查询预约。具体策略见 `browser-and-slots.md`。

有确认单后记录当地时间（英国中心使用 Europe/London，注意夏令时）、地点、申请人、费用和状态。不能把临时选中、购物车、支付进行中当作预约成功。

## 5. 一致性检查与打印

依照 `documents.md` 逐项查验：身份拼写、全程日期、住宿每晚覆盖、交通衔接、保险覆盖、证明时效、资金来源和清单要求。确认多份文件中的出行事实一致；对差异先列出，不直接改证明材料。

打印顺序服从本次官方清单，不能强制用旧案例顺序。提供每份文件页数、是否整份打印、签字位置、原件/复印件要求和仍待核实事项。需要生成 PDF 时，使用当前环境的 PDF 能力并视觉检查每页，保持条码完整和清晰；不要为了合并包破坏原始申请表或电子签名。

交付前复核最新预约状态、材料版本和过期项。用户更改行程后，旧“准备就绪”结论失效，需要重新核对受影响部分。

缺预约或待本人签署时，可以交付已核对的部分或完整打印文件，单独列出剩余动作。把“签字位置已核实”和“用户已签署”分开；用户确认纸质签署及装包后记录其确认，不改电子原件，也不把纸质签署日期自动当作官网提交日期。按材料工作规范同步全部记录，最终回复中的状态应与落盘状态一致。

## 6. 递交后

用户确认现场递交后再记录递交日期与正式收据。通过官方渠道协助查询；不以物流状态推断批准。

收到签证后，分开记录“用户报告已获签”和“已核对适用于本次旅行”。检查姓名与护照号、`VALID FOR / VALABLE POUR`（地域及排除项）、`TYPE OF VISA / TYPE DE VISA`（类别）、有效起止日期、允许停留天数、入境次数和既往使用情况。已有信息只支持日期/天数判断时，明确限定结论，再一次问清缺少的地域和类别，不能直接确认整趟旅行可使用该签证。未见贴纸图像时注明依据是用户转述，不推断未提供字段；收到贴纸也不等于保证入境。

发现字段异常指向签发机构核实。申请完成后让用户自主决定私人材料保留或删除，不擅自删除原件。
